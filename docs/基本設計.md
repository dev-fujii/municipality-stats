# municipality-stats 基本設計

状態: 確定（2026-11-15）。中の型と関数は [詳細設計](詳細設計.md) に書く。

## 目的と範囲

e-Stat の統計と気象庁の平年値を取り込み、市区町村ごとの値を出典・年・状態つきの1つのデータにまとめ、静的な HTML に書き出す Go のライブラリを作る。動かせる見本のコマンドと `example/` も置く。

満たすことは次のとおり。

- 取り込む項目は呼び出す側が引数で渡す。ライブラリは特定の項目の一覧を持たない
- 値の無い理由（調べていない・得られない・秘匿）と、取り込みの失敗を区別して返す。値が無いことを 0 にしない
- 同じ入力からは同じデータと HTML が出る。取り込みと書き出しを分け、書き出しは外部の API を呼ばない
- テストで本物の API を呼ばない
- e-Stat のアプリケーション ID は環境変数で渡し、コードやファイルに書かない

最初は群馬・栃木・長野・静岡の4県の市区町村を対象にし、全国（1,741市区町村）でも動く作りにする。

## 使うデータ

| 出どころ | 使うもの | 取り方 |
| --- | --- | --- |
| e-Stat | 社会・人口統計体系の市区町村データ（基礎データと社会生活統計指標の、廃置分合処理済みの表） | API 3.0 の getStatsData（JSON） |
| 気象庁 | 2020年平年値（気温・日最高気温・日最低気温・日照時間・最深積雪・降雪の深さの合計）と観測地点 | 「平年値ダウンロード」のアメダスの月・年別平年値と地点情報の ZIP（固定長の CSV） |
| 国土数値情報 | 行政区域（N03）。観測地点が市区町村の中にあるかの判定に使う | GeoJSON |
| e-Stat の統計GIS | 国勢調査（2020年）の 500m メッシュの人口。市区町村の代表点を求めるのに使う | 1次メッシュごとの ZIP（カンマ区切りのテキスト） |

廃置分合処理済みの表は、合併前の値も今の市区町村の境界で並ぶので、年をまたいで比べやすい。統計表 ID は基礎データが `0000020201`（A 人口・世帯）〜`0000020211`（K 安全）、社会生活統計指標が `0000020301`〜`0000020311`。

どれも商用で使える条件で配られている。国土数値情報の行政区域は CC BY 4.0、e-Stat は利用規約で商用可（CC BY 4.0 と互換）。ライブラリが加工したもの（代表点など）を使う側は、出典とは別に加工したことを書く。

### 観測地点の結び付け

市区町村ごとの代表点は、区域に中心が入る 500m メッシュの人口（総数）で重み付けした平均にする。区域の重心だと広い市町村では山の中に落ちるため。人口（総数）は秘匿されない項目なので、秘匿されたメッシュの合算を戻す処理は要らない。

観測地点は要素ごとに選ぶ。日照や積雪を測らない地点があるため。その要素の平年値がある地点のうち、区域の中の地点を先にし、無ければ代表点に一番近い地点にする。距離と標高差の上限、地点の例外の指定は呼び出す側が渡す。ライブラリは「近い地点を探す」までを持ち、「その地点を市区町村の代表に採るか」は呼び出す側が決める。標高の補正はしない。補正すると公式の値でなくなり、根拠を示しにくいため。

## 全体の構成

```
e-Stat API ──▶ estat ──┐
                       ├──▶ まとめ ──▶ データファイル ──▶ 書き出し ──▶ HTML・JSON
気象庁 ──────▶ jma ────┤
行政区域・メッシュ人口 ─▶ 地理 ┘
```

| パッケージ | 役割 | 状態 |
| --- | --- | --- |
| `estat` | e-Stat API を呼び、値と状態の並びに変える | 詳細設計あり（1-3） |
| `jma` | 気象庁の平年値の ZIP と地点情報を読む。値・単位・RMK（正常値か統計値なしか）・資料年数・統計期間を返す | これから |
| 地理 | 行政区域の読み込み、区域の中の判定、区域が接している市区町村（隣の市区町村）の判定、メッシュ人口からの代表点、近い地点の探索 | これから |
| まとめ | 市区町村ごとに値をまとめ、観測地点を結び付ける | これから |
| 書き出し | データから HTML と JSON を書き出す。テンプレートは呼び出す側が渡し、ライブラリは簡素な見本だけ持つ | これから |
| `cmd/` | 見本のコマンド | これから |

`estat`・`jma`・地理の部品は互いを知らない。まとめのパッケージがこれらを使う。パッケージ名は作るときに決める（`estat` 以外は仮の名前）。

## 入力

- 取り込む項目の一覧（統計表 ID と項目コード）と、対象の市区町村コード。呼び出す側が渡す
- e-Stat のアプリケーション ID。呼び出す側が環境変数から読んで渡す。見本のコマンドは環境変数 `ESTAT_APP_ID` を読む
- 書き出しのテンプレート。渡さなければ見本のテンプレートを使う

## 出力

- 取り込んだ値の並び。1つの値は、市区町村コード・項目・年・値・状態・単位を持つ
- まとめたデータファイル（形は詳細設計で決める）。出典と取得日も持つ
- HTML と JSON

## エラーの扱い

- 値の文字列が記号（「***」「-」「X」）のときは、エラーではなく状態として返す
- API が誤りを返したとき、通信に失敗したとき、知らない形の JSON が返ったときはエラーを返す。途中まで取れた値で続けない
- 呼び出す側は、エラーなら前のデータファイルを残して止まれるようにする

## テスト

- 標準の `testing` を使い、表で並べるテスト（table-driven）にする
- API を呼ぶ部分は `httptest` で差し替え、`testdata/` に置いた実際の返り値の JSON を返す
- `go vet`・`golangci-lint`・`go test` を CI で動かす

## 版

Go のモジュールの決まりに従い、`v0.x.y` のタグで版を付ける。外に見せる型と関数がまだ固まらないので、v1 にするまでは 0 のままにする。

- 外に見せる型や関数を変えて、使う側が直す必要があるときは x を上げる
- 使う側が直さずに済む変更（バグの修正・関数の追加・内部の整理）は y を上げる
- タグは main で CI が通った commit に付け、push する。一度 push したタグは付け直さない。Go のプロキシに残り、同じ版で中身が変わってしまうため
- 何を変えたかは GitHub のリリースの説明に書く
