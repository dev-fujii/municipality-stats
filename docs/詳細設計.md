## 1. estat パッケージ

e-Stat API 3.0 の getStatsData を呼び、値と状態の並び（`[]Record`）に変える。

### 1.1 使う API

```
GET https://api.e-stat.go.jp/rest/3.0/app/json/getStatsData
```

| パラメータ | 値 | 理由 |
| --- | --- | --- |
| `appId` | アプリケーション ID | 必須。呼び出す側が渡す |
| `statsDataId` | 統計表 ID（`0000020201` など） | 1回の呼び出しで1つの統計表 |
| `cdCat01` | 項目コードをカンマでつなぐ | 同じ統計表の項目をまとめて取る。列挙は100個まで。社会生活統計指標のコードは `#` で始まる（`#A01202`）。query は `url.Values` で組み、`%23` にして送る。文字列でつなぐと `#` から後ろがフラグメントになり、サーバーに届かない |
| `startPosition` | 前の応答の `NEXT_KEY` | 続きを取る |
| `limit` | 100000（既定） | 1回の上限。テストでは小さくして続きの取得を試す |
| `metaGetFlg` | `N` | 項目名や地域名は使わないので、応答を小さくする |

`cdArea` は指定せず、全国の地域を取ってから呼び出す側の地域の一覧で絞る。`cdArea` の列挙は100個までなので、対象が100を超えると分けて呼ぶ必要があり、全国に広げると18回に分かれる。全国を取れば、対象がいくつでも同じ呼び方で済む。件数は、地域（約1,900。都道府県・政令市の区を含む）× 項目 × 年で、1つの統計表で10万件を超えるときは続きを取る。2026-11-15 に18個の項目（8つの統計表）で試すと、統計表ごとに約1.1万〜16.8万件、計約52万件で、続きを含めて11回ほどの呼び出しで済んだ。`cdArea` と `cdCat01` に101個を渡すと、`STATUS` 105（「値が多すぎます。100個以内で指定して下さい」）が返ることも同じ日に確かめた。

`replaceSpChars`（記号を 0 や NULL に置き換える）は使わない。記号の違いが値の無い理由を表すので、そのまま受け取る。

### 1.2 返り値の形

2026-11-15 に統計表 `0000020208`（住宅）を呼んで確かめた形。

```json
{
  "GET_STATS_DATA": {
    "RESULT": { "STATUS": 0, "ERROR_MSG": "正常に終了しました。", "DATE": "2026-11-15T16:35:00.175+09:00" },
    "PARAMETER": { "STATS_DATA_ID": "0000020208", "START_POSITION": 1, "LIMIT": 4 },
    "STATISTICAL_DATA": {
      "RESULT_INF": { "TOTAL_NUMBER": 34, "FROM_NUMBER": 1, "TO_NUMBER": 4, "NEXT_KEY": 5 },
      "TABLE_INF": { },
      "DATA_INF": {
        "NOTE": [
          { "@char": "***", "$": "調査又は集計していないもの" },
          { "@char": "-", "$": "データが得られないもの" },
          { "@char": "X", "$": "数値が秘匿されているもの" }
        ],
        "VALUE": [
          { "@tab": "00001", "@cat01": "H2130", "@area": "10201", "@time": "2023100000", "@unit": "ｍ2", "$": "102.55" },
          { "@tab": "00001", "@cat01": "H2130", "@area": "10424", "@time": "2023100000", "@unit": "ｍ2", "$": "-" }
        ]
      }
    }
  }
}
```

確かめて分かったこと:

- `VALUE` は配列だが、1件だけのときは配列でなくオブジェクト1つになる
- 値は `$` に文字列で入る。数のほか、記号「***」「-」「X」が入る。人口の少ない町村の住宅の項目は「-」で返る
- `NEXT_KEY` は数で、続きがあるときだけある
- `@time` は `2023100000` の形で、先頭4桁が年
- `@unit` は全角の文字を含む（`ｍ2`）
- `RESULT.STATUS` は 0 が正常。1 は「正常に終了しましたが、該当データはありませんでした」で、このとき `DATA_INF` が無い。appId が違うと 100
- `PARAMETER` に appId は入らない。実際の応答を `testdata/` に置いても appId は漏れない
- 続きの応答（2ページ目以降）にも `NOTE` が載り、そのページの `VALUE` に出ない記号も含めて3つとも並ぶ。2026-11-21 に `0000020208` の `H2130` を `limit` 1000 で取り、13ページ・12,859件がエラーなく `Record` になった

未確認: `NOTE` が1件だけのときもオブジェクト1つになるか。`VALUE` と同じく両方を読めるようにする。STATUS 2 以上で 100 未満の意味。調べていない年の行が「***」で返るのか、行そのものが無いのか（2章の Latest の決め方に関わる）。項目コードをつなぐカンマが `%2C` で届いても読まれるか。

### 1.3 値の文字列の読み取り

値の文字列を、元の文字列と状態に変える。

```go
type Status int

const (
	StatusUnset        Status = iota // 未設定（ゼロ値）。正しい値としては使わない
	StatusOK                         // 数が入っている
	StatusNotSurveyed                // 「***」調査又は集計していない
	StatusUnavailable                // 「-」データが得られない
	StatusConfidential               // 「X」秘匿されている
)

type Value struct {
	Raw    string // e-Stat の "$" そのまま（"102.55" の桁を保つ）
	Status Status
}

func parseValue(s string) (Value, error)
```

決まり:

- 記号は3つを別々の状態にする。「公表値なし」のようにページに出す言葉へまとめるのは呼び出す側でする。取り込みの段階でまとめると、あとから理由を区別できない
- 数は `-?[0-9]+(\.[0-9]+)?` の形だけを受け付ける。「-」だけなら記号、「-12.3」なら負の数（人口増減率は負になる）
- 知らない記号、空の文字列、カンマを含む数はエラーにする。「不明」の状態で通すと、API の変化や読み漏れに気づけない
- 値は float64 にせず、文字列のまま持つ。計算するときに `math/big.Rat` に変え、丸めは表示の直前に1回だけする。float64 だと 102.55 が 102.5499… になり、四捨五入で桁がずれる
- 取り込みの失敗はここでは扱わない。失敗は `Client` がエラーで返し、呼び出す側がデータファイルに残す
- ゼロ値を OK にしない（2026-11-16 決定）。初期化を忘れた `Value{}` や、エラーのときの返り値が「数が入っている」と読めないようにするため。未設定の状態と、知らない番号の状態は、計算と保存の入口でエラーにする

`NOTE` に知らない記号が載っていたら、`Client` がエラーにする。記号の意味が変わったことに気づくため。記号ごとの意味の文も、空白をそろえてから期待の文（「調査又は集計していないもの」「データが得られないもの」「数値が秘匿されているもの」）と照らし、違えばエラーにする。「-」が「該当数値なし」を表す統計もあるので、社会・人口統計体系でない表を渡されたときに止まれる（2026-11-16 決定）。

`VALUE` に記号の値があるのに、同じ応答の `NOTE` にその記号が載っていなければエラーにする。`NOTE` が無いときも同じ。載っていない記号は意味の文を照らせないので、別の意味の「-」が「データが得られない」として入るのを防ぐ（2026-11-16 決定）。

テストの表:

| 入力 | 状態 | エラー |
| --- | --- | --- |
| `102.55` | OK | なし |
| `0` | OK | なし |
| `-12.3` | OK | なし |
| `***` | NotSurveyed | なし |
| `-` | Unavailable | なし |
| `X` | Confidential | なし |
| `x`（小文字） | | あり |
| 空 | | あり |
| `1,234` | | あり |
| `1e3` | | あり |

### 1.4 JSON を読む型

JSON の形をそのまま写す型はパッケージの外に出さず、外には `Record` だけを見せる。

```go
type Record struct {
	TableID string // 統計表 ID
	Code    string // 項目コード（@cat01）
	Area    string // 地域コード（@area。5桁）
	Year    int    // @time の先頭4桁
	Unit    string // @unit
	Value   Value
}
```

- `VALUE` と `NOTE` は、配列とオブジェクト1つのどちらでも読める型にする。`UnmarshalJSON` で先頭の文字が `[` か `{` かを見る
- `@time` は10桁の数字で、後ろの6桁が `100000`（年の値）でなければエラーにする。社会・人口統計体系の年の表だけを扱うための決まりで、e-Stat のほかの表の時点コードには当てはめない。四半期や月の値が年として入るのを防ぐ（2026-11-16 決定）
- `VALUE` のキーは `@tab`・`@cat01`・`@area`・`@time`・`@unit`・`$` だけを受け付け、ほかのキー（`@cat02` など）があればエラーにする。`@unit` のほかのキーが欠けていてもエラーにする。`@tab` は1つの統計表の中で同じ値でなければエラーにする。「同じ Record が2つ」の検査だけでは、分類の値が1つだけの表をすり抜けるため（2026-11-16 決定）
- `@unit` のほかのキーは、値が空の文字列のときと `null` のときも、欠けたときと同じくエラーにする。項目コードや地域コードが空の `Record` を作らないため（2026-11-16 決定）
- 同じ統計表・項目・地域・年の `Record` が2つあればエラーにする。社会・人口統計体系の表は分類が `@cat01` だけなので、ほかの分類（`@cat02` など）がある表を渡したときに気づける

### 1.5 Client

```go
type Client struct { /* baseURL・appID・httpClient・limit */ }

func NewClient(appID string, opts ...Option) (*Client, error)
func WithBaseURL(u string) Option        // テストで httptest のサーバーに向ける
func WithHTTPClient(h *http.Client) Option
func WithLimit(n int) Option             // 既定は 100000

type Query struct {
	TableID string
	Codes   []string // 1〜100個
}

func (c *Client) GetStatsData(ctx context.Context, q Query) ([]Record, error)
```

- `appID` が空なら `NewClient` がエラーを返す。appId を環境変数から読むのは呼び出す側（見本のコマンドは `ESTAT_APP_ID`）
- `NEXT_KEY` があれば、それを `startPosition` にして続きを取る。`NEXT_KEY` が前の `startPosition` 以下なら、終わらない繰り返しを防ぐためにエラーにする。最後に件数が `TOTAL_NUMBER` と合うか確かめる
- `STATUS` が 0 以外なら `*APIError{Status, Message}` を返す。1（該当データなし）は `ErrNoData` を包んで返し、呼び出す側が `errors.Is` で見分けられるようにする。項目コードの書き違いで起きるので、黙って空にしない
- 応答に `RESULT.STATUS` が無ければエラーにする。e-Stat でない JSON を 200 で返されたとき、空の結果を成功として返さないため
- HTTP の状態が 200 以外ならエラー
- エラーの文に appId を入れない。通信の失敗で返る `*url.Error` は、文にも `URL` のフィールドにも URL を丸ごと含む。`%w` で元のエラーを包むと鎖の中に URL が残るので、URL から appId を消した新しい `*url.Error` を作り、`Err` だけを引き継ぐ（`context.Canceled` は `errors.Is` で見分けられるまま）。`APIError` の文に appId が入っていれば消す。ログと GitHub Actions の出力に appId が出るのを防ぐ
- リダイレクトは追わない。`CheckRedirect` で止め、200 以外としてエラーにする。追うと、次の要求の Referer に appId つきの URL が入るため。`WithHTTPClient` で渡された `http.Client` は写しを作ってから設定し、呼び出す側の値を書き換えない（2026-11-16 決定）
- `WithBaseURL` は https だけを受け付ける。テストのために、ループバックのホスト（`127.0.0.1`・`localhost`・`[::1]`）だけ http を許す（2026-11-16 決定）
- appId は、`String`・`GoString`・`LogValue`・`MarshalJSON` が伏せ字を返す型で持つ。構造体ごと `%+v` や `log/slog` で出しても漏れないようにするため（2026-11-16 決定）
- `ctx` が取り消されたら止める。待ち時間は `http.Client` の `Timeout`（既定60秒）で決める。未確認: 10万件の応答が60秒に収まるか。Client を作ったときに大きさと時間を測る
- 呼び出しは1つずつ順に行い、並べて呼ばない。再試行もまだしない（定期実行は手で動かし直せる）。測った結果を見て、5xx と時間切れだけ2回までやり直す形を足すかを決める

## 2. 指標の計算

取り込んだ `Record` から、呼び出す側が渡す指標の定義に従って表示の値を計算する部品を公開側に置く。定義の中身（どの項目をどう組むか、何を比べるか、文章）は呼び出す側が持つ。確定している決まりは次のとおり。2.1以降は 2026-11-22 に確定。

- 計算は3つ。Value は項目1つの値、Ratio は同じ年の a ÷ b、Diff は基準の年を最後にした連続 N 年（基準の年が Y なら Y−N+1 から Y まで）の Σ(a − b)。結果には年の範囲を持たせる
- 年の決め方は2つ。Fixed は決めた年。Latest は、使う項目のすべてについて、対象の地域のどれか1つに「調べていない（***）」でない行がある最新の年（2026-11-16 決定）。「調べていない」だけの年は、調査の無い年として飛ばす。その年の値が秘匿や「得られない」の地域は、その状態のまま出す。年は地域ごとではなく、指標ごとに対象の全地域で1つに決める。町ごとに年がずれると比べられないため
- 換算の倍率（scale）は計算のあとに掛け、丸めは最後に1回だけ四捨五入する。負の数は絶対値で四捨五入する（-1.25 を小数1桁にすると -1.3）
- 倍率は `*big.Rat` で受け取る。float で受け取ると 0.1 が正確な 0.1 にならないため。文字列から `*big.Rat` を作るのは呼び出す側で、部品は受け取った `*big.Rat` を書き換えない
- 文字列から `*big.Rat` を作る呼び出す側は、`big.Rat.SetString` の前に形を確かめる。`SetString` は `1e-1`・`0x10`・`1_000`・`+0.1` も読み、分数の形では先頭の 0 を8進数として読む（`1/010` は 1/8）ため
- 入力に OK でない値があれば、結果も OK にしない。状態が混ざったときは、秘匿、得られない、調べていない、の順で強いほうを結果の状態にする。0 で割るときは「計算できない」、N 年のうち1年でも行が無ければ「年が足りない」の状態にし、途中までの合計を出さない。この2つは、取り込みの状態（`estat.Status`）とは別の型で持つ。未設定の状態と不正な入力はエラーにする（2026-11-16 決定）
- 最新の共通の年の値が秘匿でも、黙って前の年に戻さない

2026-11-22 に19項目・172市区町村の取り込み結果を年・状態ごとに集計した。対象の行に「***」は0件で、調査の無い年は行そのものが返らなかった。たとえば `H2130` の1983・1988・1993・1998年は、172地域のうち57地域だけに行がある。「得られない」の行はあり、`#I0910103` の1980年は77地域が該当した。これは確認した項目・地域・取得時点の結果であり、ほかの入力でも「***」が返らないとは決めない。「***」の行がある形と行そのものが無い形のどちらでも同じ年が選ばれることを、テストで確かめる。

### 2.1 パッケージと入力

パッケージ名は `indicator`、置き場所は `indicator/`、import path は `github.com/dev-fujii/municipality-stats/indicator` とする。入力は `[]estat.Record` にする。基本設計の汎用の出力には `estat.Record` が含まれ、この計算に必要な地域・項目・年・値・状態がそろっているため。

`indicator` は標準ライブラリと `estat` に依存し、まとめ・`jma`・地理には依存しない。まとめのパッケージは取り込んだ `estat.Record` を渡す。`estat` から `indicator` への依存は作らず、`estat`・`jma`・地理が互いを知らない構成を保つ。気象・地理の値を計算するための汎用の入力型は、まとめの設計で別途決める。この章では `jma.Value` などを `estat.Record` に詰め替える決まりは作らない。

通信、取り込み、保存はしない。対象の地域は呼び出す側が `areas []string` で渡す。行から地域の集合を作らず、行が1つも無い地域も結果に残す。`areas` は1件以上、各コードは ASCII の数字5桁、重複不可。返す結果は `areas` と同じ順にし、地域を自動で追加しない。

### 2.2 指標の定義

```go
type Operation int

const (
	OperationUnset Operation = iota
	OperationValue
	OperationRatio
	OperationDiff
)

type YearRule int

const (
	YearRuleUnset YearRule = iota
	YearRuleLatest
	YearRuleFixed
)

type Item struct {
	TableID string
	Code    string
}

type Definition struct {
	Op        Operation
	A         Item
	B         *Item
	YearRule  YearRule
	FixedYear int
	SpanYears int
	Scale     *big.Rat
	Decimals  int
}

func ValidateDefinition(d Definition) error
```

`Item` は統計表 ID と項目コードの組で識別する。同じ項目コードでも統計表が違えば別の項目。`Definition` にマスターデータの ID、表示名、単位、文章、比較の設定は持たせない。定数の番号はこのパッケージ内のもので、呼び出す側の定義の番号に合わせない。

`ValidateDefinition` は次の条件を表の順に確かめ、最初の違反を2.6の `*DefinitionError` で返す。

| フィールド | 受け付ける条件 |
| --- | --- |
| `Op` | Value・Ratio・Diff のいずれか。未設定と未知の番号は不可 |
| `A` | `TableID`・`Code` とも空でなく、前後に空白がない |
| `B` | Value は nil。Ratio・Diff は必須で、`A` と同じ項目の条件を満たす。`A` と同じ組も許す |
| `YearRule` | Latest・Fixed のいずれか。未設定と未知の番号は不可 |
| `FixedYear` | Fixed は正の年。Latest は0。0を「今年」に読み替えない |
| `SpanYears` | 1以上。Value・Ratio は1に限り、Diff だけ複数年を許す |
| `Scale` | nil でなく `Sign() > 0`。0と負の倍率は不可 |
| `Decimals` | 0以上。表示の小数点以下の桁数。0・1に限定しない |

年は西暦の正の整数として扱う。倍率の文字列を受け取る関数は公開しない。呼び出す側が形を確かめて作った `*big.Rat` を渡す。検査と計算は `Scale`・`B` を含めて引数を書き換えない。呼び出し中は呼び出す側も引数を書き換えない。

### 2.3 入力の検査と値の変換

`SelectYears` と `Calculate` は、定義、対象地域、渡された全 `Record` の順に検査する。全行の検査を終えてから対象地域・項目で絞る。対象外の地域・項目・年の行でも、不正な状態や重複はエラーにする。行の並びは問わず、nil・空の `records` は正しい入力として扱う。

| `Record` のフィールド | 検査 |
| --- | --- |
| `TableID`・`Code` | 空でなく、前後に空白がない |
| `Area` | ASCII の数字5桁 |
| `Year` | 正の整数 |
| `Value.Status` | `estat.StatusOK`・`StatusNotSurveyed`・`StatusUnavailable`・`StatusConfidential` のいずれか。未設定・未知の番号はエラー |
| `Value.Raw` | OK は `^-?[0-9]+(\.[0-9]+)?$`。NotSurveyed は `***`、Unavailable は `-`、Confidential は `X` と完全一致 |
| 行の重複 | 同じ `TableID`・`Code`・`Area`・`Year` の行は、値が同じでもエラー |

`estat.Value` が公開しているのは `Raw` と `Status` だけで、`parseValue` は非公開。そのため計算の入口でも上の形と状態の対応を検査する。OK の `Raw` は検査後に `new(big.Rat).SetString(raw)` で変換し、変換できなければエラーにする。float は通さない。指数、分数、16進数、`+`、カンマ、空白を `SetString` だけで受け付けない。`001.20` は10進の `6/5`、`-0.0` は数の0として扱う。

記号は数に変換しない。`Unit` は結果に写さず、単位の整合や換算は推測しない。a・b の組み合わせと倍率が意味を持つことは定義を作る側が確認する。

### 2.4 年の決め方

```go
type YearRange struct {
	StartYear int
	EndYear   int
}

func SelectYears(d Definition, areas []string, records []estat.Record) (YearRange, bool, error)
```

第2返り値は基準の年を決められたかを表す。Fixed は行の有無にかかわらず true。Latest で候補年が無ければ `YearRange{}, false, nil` を返す。不正な入力は `YearRange{}, false, error`。年を決められないことと、入力の誤りを区別する。

Fixed は `Y = FixedYear`。Latest は次の手順で `Y` を1つ決める。

1. `areas` に含まれる地域、かつ定義で使う項目（Value は a、Ratio・Diff は a と b）の行だけを年ごとに見る。
2. 項目ごとに、その年に少なくとも1地域で `StatusNotSurveyed` 以外の行があるかを調べる。OK・Unavailable・Confidential はいずれも候補に数える。行なしと NotSurveyed だけの場合は数えない。
3. 使うすべての項目が条件を満たす年のうち、最大の年を `Y` にする。a の行がある地域と b の行がある地域は同じでなくてもよい。全地域の行がそろうことや、数値が得られる地域があることは条件にしない。

Value・Ratio は `StartYear = EndYear = Y`。Diff は `StartYear = Y - (SpanYears - 1)`、`EndYear = Y`。Latest の探索は基準の年だけに行い、Diff の途中年が欠けていることを理由に前の基準年へ戻さない。範囲の年が0以下になる場合も式の範囲を保持し、正の年でない部分には行が無いので計算時に「年が足りない」とする。

`SelectYears` は地域ごとに年を選ばず、指標1つに対して1回だけ呼ぶ。Fixed で行が無くても、返す範囲は指定した年のまま。範囲に必要な行があるかの判定は `Calculate` が地域ごとに行う。

### 2.5 計算と結果

```go
type CalculationStatus int

const (
	CalculationStatusUnset CalculationStatus = iota
	CalculationStatusOK
	CalculationStatusDivisionByZero
	CalculationStatusInsufficientYears
)

type Result struct {
	Area              string
	Value             *big.Rat
	Display           string
	Years             *YearRange
	InputStatus       estat.Status
	CalculationStatus CalculationStatus
}

func Calculate(d Definition, areas []string, records []estat.Record) ([]Result, error)
```

`Calculate` は2.3の検査を済ませ、2.4の手順で年を1つ決めてから、各地域について計算する。内部で検査・年の決定を共用し、同じ `Calculate` の中で全行の検査を二重に行う必要はない。不正な入力では `nil, error` を返し、途中までの結果は返さない。

`Value` は倍率を掛けたあとの、丸める前の値。`Display` は丸めた値だけの文字列で、単位・桁区切り・先頭の `+` は付けない。数値を返せるのは `InputStatus == estat.StatusOK` かつ `CalculationStatus == CalculationStatusOK` の場合だけで、それ以外は `Value: nil, Display: ""`。有効な0は nil でない `*big.Rat` として返す。`Value` は入力の倍率やほかの結果と共有せず、呼び出す側が変更しても影響を残さない。

`Years` は計算に使う予定の範囲であり、値が得られなくても保持する。結果ごとに別の `YearRange` を持たせる。Latest で候補年が無い場合だけ nil にし、対象の全地域に InsufficientYears を返す。この場合、評価する範囲が無いため `InputStatus` は集約の初期値である OK とする。

地域ごとの状態は次のように決める。2つの状態を1つの列挙型にまとめない。

| 状態 | 決め方 |
| --- | --- |
| `InputStatus` | 必要な地域・項目・年のうち、存在する全行から最も強い状態を採る。Confidential ＞ Unavailable ＞ NotSurveyed ＞ OK。行が1つも無ければ初期値の OK。OK だけでは数値が得られた意味にならず、計算の状態も必ず見る |
| `CalculationStatusInsufficientYears` | 必要な行が1つでも無い。Value・Ratio の1年も対象。記号の行は「行がある」と数え、行なしを NotSurveyed に置き換えない |
| `CalculationStatusDivisionByZero` | 必要な行がすべてあり、Ratio の b が OK で数の0。a が秘匿などでも b の0が分かればこの状態を併記する |
| `CalculationStatusOK` | 上の2条件に当たらない。入力に記号があっても、年不足・0除算が無ければこの状態。数値の有無は `InputStatus` と合わせて判断する |

先に存在する必要行の状態をすべて集約するので、欠けた年を見つけても秘匿などを読み落とさない。計算の状態は年不足を先に判定し、その場合は0除算を判定しない。たとえば Ratio の a が無く b が0なら InsufficientYears、a が秘匿で b が0なら InputStatus は Confidential、CalculationStatus は DivisionByZero になる。b が記号なら0とはみなさない。返す結果に未設定の状態は含めない。

両方の状態が OK のときだけ、次の式を有理数のまま計算する。

| 計算 | 倍率を掛ける前の値 |
| --- | --- |
| Value | `a[Y]` |
| Ratio | `a[Y] / b[Y]` |
| Diff | `Σ(a[y] - b[y])`。`StartYear <= y <= EndYear` の連続する全整数年 |

最後に `Scale` を掛けて `Value` に入れる。入力ごと・年ごと・差ごとには丸めない。`Display` は `Value` の絶対値を `10^Decimals` 倍し、分子を分母で割った整数商と余りを使って作る。余りの2倍が分母以上なら商を1増やし、元の符号を戻して小数点を置く。丸めた商が0なら負号を付けない。常に指定の小数桁数を保ち、`Decimals: 1` の整数2は `"2.0"`、0は `"0.0"`。`Decimals: 0` なら小数点を付けない。`Value` 自体は丸めない。

### 2.6 エラー

```go
var (
	ErrInvalidDefinition = errors.New("indicator: invalid definition")
	ErrInvalidArgument   = errors.New("indicator: invalid argument")
	ErrInvalidRecord     = errors.New("indicator: invalid record")
	ErrDuplicateRecord   = errors.New("indicator: duplicate record")
)

type DefinitionError struct {
	Field string
	Err   error
}

func (e *DefinitionError) Error() string
func (e *DefinitionError) Unwrap() error

type InputError struct {
	Index int
	Area  string
	Item  Item
	Year  int
	Field string
	Err   error
}

func (e *InputError) Error() string
func (e *InputError) Unwrap() error
```

`ValidateDefinition` の失敗は `ErrInvalidDefinition` を包む `*DefinitionError`。`SelectYears`・`Calculate` も同じ型を返す。`Field` は `Op`・`A.TableID`・`B`・`B.Code`・`YearRule`・`FixedYear`・`SpanYears`・`Scale`・`Decimals` のように、誤ったフィールドを特定する。

地域や行の誤りは `*InputError`。`Index` は元の `areas` または `records` の0始まりの位置で、位置が無い場合だけ -1。`Field` は `Areas`・`Areas[i]`、または `Records[i].Value.Status` のように引数とフィールドを特定する。行の重複は2行目の位置を指し、`Field` は `Records[i]`。`Area`・`Item`・`Year` は分かっている値を入れ、該当しない項目はゼロ値にする。

| エラーにする場合 | 包むエラー |
| --- | --- |
| 未設定・未知の計算や年の決め方、a・b の不足や余分な b、不正な年・年数・倍率・桁数など2.2の違反 | `ErrInvalidDefinition` |
| `areas` が nil・空、地域コードの形が違う、同じ地域が2つ | `ErrInvalidArgument` |
| 行の項目・地域・年が不正、状態が未設定・未知、Raw と状態が不一致、数の形が不正・変換できないなど2.3の違反 | `ErrInvalidRecord` |
| 同じ統計表・項目・地域・年の行が2つ | `ErrDuplicateRecord` |

`Unwrap` は `Err` を返す。`Error` は場所と原因を含め、文全体の一致は契約にしない。数の変換などの元のエラーがある場合は `errors.Join` で分類用のエラーと両方を残す。呼び出す側は `errors.Is` で分類し、`errors.As` でフィールドや行の位置を取り出せる。

秘匿・得られない・調べていない、0除算、行なし、Latest の候補年なしはエラーにしない。後ろの3つは計算の状態として返す。

### 3.2 geo の入力と読み取り

```go
type ZIPSource struct {
	Name   string
	Reader io.ReaderAt
	Size   int64
}

type Point struct {
	Latitude  *big.Rat
	Longitude *big.Rat
}

type Boundaries struct { /* 非公開フィールド */ }

func ReadN03(sources []ZIPSource, rollup map[string]string) (*Boundaries, error)

type PopulationCell struct {
	MeshCode string
	People   int64
}

type ElevationCell struct {
	MeshCode string
	Meters   *big.Rat
}

func ReadPopulation(sources []ZIPSource) ([]PopulationCell, error)
func ReadElevation(sources []ZIPSource) ([]ElevationCell, error)
func MeshCenter(meshCode string) (Point, error)
```

`sources` は空にできず、Name はエラーの出典名で重複不可、Reader は nil 不可、Size は正とする。受け取った Reader は閉じない。ファイルの開閉、URL、取得日時、ハッシュは呼び出す側が持つ。全体を読み終えて ZIP の CRC まで検査し、失敗したら部分結果を返さない。通常ファイルを展開先へ書き出さない。必要なファイルが0または複数ならエラー。メタデータや shp 等は読み飛ばし、同じ ZIP 内の必要な項目の重複は断る。

この章の関数は入力の配列・対応表・数値を変更しない。入力の数値を保持して返す場合も big.Rat/big.Int をコピーし、呼び出し後の変更が別の値へ伝わらないようにする。AreaCodes/PrimaryMeshes は ReadN03 が成功して返した非 nil の Boundaries に対して呼ぶ。

`ReadN03` は各 ZIP の `N03-<基準日>_<県番号>.geojson` を1つ読む。UTF-8 の FeatureCollection と、Polygon・MultiPolygon だけを受け付ける。crs は EPSG:6668 またはその URN を受け付け、異なる座標系・省略は推測しない。座標は `json.Number` から10進の桁を直接読み、10^15を掛けた int64 にする。float や big.Rat を経由せず、15桁未満は末尾に0を補う。15桁を超える非ゼロの桁がある入力は丸めずエラーにし、対応する精度と整数の範囲を見直す。小数部の末尾の0は桁の制限前に取り除いてよい。

2次元・緯度経度の範囲・閉じた輪・閉じ点を含む4点以上・異なる点が3点以上・面積0でないことを検査する。面積は符号つきの靴紐公式で求め、積は128ビット、輪全体の和だけ big.Int にして桁あふれを避ける。輪の向きには依存しない。外輪・穴それぞれの外接矩形も読み込み時に作る。ここまでを頂点数に比例する検査とし、辺の全組み合わせを調べない。

自己交差、穴どうしの交差、穴の外輪からのはみ出し、異なる地物の重なりの事前の全検査は行わず、これらの位相は配布元の N03 を信頼する。数十万頂点で2乗の検査をしないため。外接矩形だけで穴の正しさを保証したことにはしない。Locate が実際に問い合わせた点で異なる区域の内部の重なりを検出した場合は、3.3のとおりエラーにする。この読み取りを任意の GeoJSON の完全な妥当性検査としては使わない。

`N03_007` が null または空の地物は所属未定地として除く。それ以外は数字5桁を要求する。同じコードの地物は飛び地も含め、ポリゴンの集まりとして保持する。`rollup` は呼び出す側が渡す元の区コード→市コード。キーと値は数字5桁、自己対応・連鎖・循環を断る。nil は統合なし。同じ市に写る区のポリゴンをまとめる。対応表や対象県の一覧をパッケージ内に置かない。

`ReadPopulation` は `tblT001141H<1次番号>.txt` のみを人口ファイルとして読む。Shift_JIS を厳密に復号し、不正なバイトと U+FFFD を断る。`encoding/csv` を使い、LF・CRLF・最終改行なしを受け付ける。1行目の54列の名前と順、2行目の54列・最初の4列の空欄・5列目の人口総数の表題を検査する。2行目の残る49項目名は計算に使わず、列数だけを検査する。データは54列、KEY_CODE は数字9桁、総人口は非負の10進整数で int64 の範囲内。空欄・`-`・`X` 等を0にしない。総人口が秘匿されない前提を満たさない入力はエラーにする。他の49項目の記号や HTKSYORI により総人口を移し替えない。

`ReadElevation` は `G04-c-11_<1次番号>-jgd.xml` を `encoding/xml` で読む。先頭の UTF-8 BOM を除いてよい。名前空間 URI と構造を確かめ、同じ名前の別名前空間を読まない。tupleList の前後の空白行を除き、各行10列で読む。メッシュコードは数字9桁、平均標高は符号つき10進整数または小数で `big.Rat` にする。指数表記・NaN・Inf は断る。平均標高の `unknown` は `Meters: nil` とし、0m・負の標高と区別する。使わない8列は列数だけを確かめる。各行の先頭8桁が親の `ksj:tertiaryMeshCode` と一致することも確かめる。G04-c の幾何の座標は使わず、人口と同じメッシュコードで結ぶので、JGD2000 のポリゴンを変換して重ねない。

GML の表題に当たる `gml:CompositeValue` の recordType が3.1の10項目の順であり、平均標高の QuantityList の uom が m であることを検査する。各 DataBlock の rangeParameters がその recordType を参照することも確かめ、列の意味が異なる資料を同じ番号だけで読み込まない。

人口・標高はそれぞれメッシュコード順に返す。複数 ZIP 間も含めた同じメッシュの重複は、値が同じでもエラー。各行の1次番号とファイル名が一致し、2次番号の2桁は0〜7、3次番号の2桁は0〜9、4次の末尾は1〜4であることを共通に検査する。`MeshCenter` は南西から1・2、北西から3・4の順の区画を使い、中心の緯度経度を正確な有理数で返す。人口行が無いセルを、読み込み側で作り足さない。

### 3.3 区域の所属

```go
type Location struct {
	AreaCode   string
	OnBoundary bool
}

func (b *Boundaries) Locate(point Point) (Location, error)
func (b *Boundaries) AreaCodes() []string
func (b *Boundaries) PrimaryMeshes() []string
```

`Locate` は区域の外なら AreaCode を空、OnBoundary を false として成功する。これは読み込んだ区域のどこにも入らないという意味であり、世界中の区域で所属が無いとは断定しない。AreaCodes は統合後のコードを昇順で返す。

PrimaryMeshes は有効な区域と面積を持って交差する1次メッシュの番号を昇順・重複なしで返す。外接矩形だけで範囲を広げず、穴を除いた面との交差で求める。枠の辺に触れるだけなら含めない。呼び出す側が必要な ZIP の範囲を照合するために使う。

点が外輪の内側で、穴の内側でなければ所属する。穴の境界も区域の境界に含める。区域、ポリゴン、輪の外接矩形で先に絞り、残った輪だけを調べる。境界を除外しないよう矩形の上下限を含める。辺も緯度の最小値から最大値までに点があるものだけを候補とし、水平辺も境界上の判定には残す。外接矩形は最初から入れ、格子の索引は3.7の計測後とする。

所属判定の共通の単位は1 / (3×10^15)度とする。N03 の固定小数点整数を3倍して使い、問い合わせの Point は最初に1回だけこの整数へ正確に換算する。メッシュ中心の緯度の分母480・経度の分母320、JMA の分母600はどれも3×10^15を割り切るので、点を境界のどちら側へも丸めない。Point の big.Rat は API と加重平均のために残すが、辺ごとの演算には使わない。この単位で正確に表せない Point は ErrInvalidArgument とし、代表点の加重平均を再び Locate へ渡す用途は契約に含めない。Representatives は平均を取る前のメッシュ中心を Locate に渡す。

線分上の判定は整数の外積0と端点間の範囲で行う。外積は `(bx-ax)*(py-ay) - (by-ay)*(px-ax)`。座標の絶対値は最大180×3×10^15、差の絶対値は最大360×3×10^15で int64 に収まり、2つの積の差の絶対値は2^121未満なので符号つき128ビットに収まる。各積の絶対値を math/bits.Mul64 の上位・下位64ビットで求め、符号を別に扱って正確に加減する。符号つき int64 の積で計算してから桁あふれを調べる方法は使わない。面積の累積を除き、big.Int/big.Rat を各辺で生成しない。

内外は半開区間による ray casting とし、水平な辺と頂点の扱いを固定して交差を二重に数えない。交点の割り算はせず、緯度をまたぐ辺の向きと外積の符号で左右を判定する。許容誤差は使わない。複数区域の境界に一致したら、rollup 後のコードの小さい区域へ入れる。同じ市内の区境界は市としての所属を変えない。異なる区域の内部が重なる点はデータの不整合としてエラーにし、コード順で隠さない。

OnBoundary は入力したポリゴンの輪の上にあるかを残す補足情報とする。同じ市にまとめた区の共有辺でも true になるが、所属は同じ市の1件になる。

### 3.4 代表点と標高

```go
type Representative struct {
	AreaCode              string
	Point                 *Point
	Population            *big.Int
	ElevationMeters       *big.Rat
	State                 RepresentativeState
	ElevationState        ElevationState
	MissingElevationMeshes []string
}

type RepresentativeState string
const (
	RepresentativeOK           RepresentativeState = "ok"
	RepresentativeNoPopulation RepresentativeState = "no_population"
)

type ElevationState string
const (
	ElevationOK           ElevationState = "ok"
	ElevationMissing      ElevationState = "missing_mesh"
	ElevationNoPopulation ElevationState = "no_population"

func Representatives(b *Boundaries, population []PopulationCell,
	elevation []ElevationCell, areaCodes []string) ([]Representative, error)
```

`areaCodes` は統合後のコードの重複なしの集合。全コードが区域に存在することを確かめ、昇順の結果を返す。人口・標高の入力は同じ検査を通し、並びに依存せずメッシュ番号順に処理する。API の入力・返り値の big.Rat・big.Int は所有を分けてコピーし、入力や返り値の変更が他の結果へ伝わらないようにする。

人口1人以上の各メッシュの中心を Locate で所属させ、該当する町に足す。境界をまたいでも人口を分けず、区域の外・対象の外は足さない。人口0のセルは重み0であり、標高の欠損判定に使わない。Σ人口を big.Int、Σ(人口×中心緯度)、Σ(人口×中心経度)、Σ(人口×平均標高)を big.Rat で求め、Σ人口で割る。地点の座標で地面の標高を調べ直さず、標高による気候の補正もしない。

Σ人口が0なら Point と ElevationMeters は nil、Population は数の0、State と ElevationState は no_population にする。役場や区域の重心へ自動で置き換えない。人口が正でも、1セルでも標高の行が無い・Meters が nil なら ElevationMeters は nil、ElevationState は missing_mesh、その番号を昇順で返す。残りのセルだけで標高を平均しない。代表点は人口だけで求められるので State は ok を保つ。代表点が区域の外へ出ても移し替えない。

### 3.5 climate の要素ごとの候補

```go
type StationLocation struct {
	StationID string
	Point     geo.Point
	AreaCode  string
	OnBoundary bool
}

type Candidate struct {
	StationID              string
	Inside                 bool
	DistanceMeters         float64
	ElevationDifferenceMeters *big.Rat
}

func LocateStations(b *geo.Boundaries, stations []jma.Station) ([]StationLocation, error)
func Candidates(origin geo.Representative, stations []jma.StationNormals,
	locations []StationLocation, element jma.Element) ([]Candidate, error)
func Distance(a, b geo.Point) (float64, error)
```

`LocateStations` は jma の TotalMinutesTenths を600で割った有理数の Point を Locate に渡す。全国の地点を入力してよい。所属は元の区域コードを保存せず、rollup 後のコードまたは空。地点 ID 順に返し、OnBoundary も保存する。地点 ID は数字5桁を要求し、重複はエラー。Candidates も stations/locations の ID と重複を同じ条件で検査する。

`Candidates` は要素を1つ受け、`Normal.Annual.Status == jma.StatusOK` の地点だけを返す。月に欠損があることだけでは年の候補から除かない。積雪の有効な0も候補。求めた要素の Normal が無い・重複する・未設定の状態を持つ場合は、不完全な入力としてエラー。RMK による unavailable は正常な候補外とする。地点情報の印だけで平年値の有無を判断しない。

stations に出てくる全 ID の locations がちょうど1つ存在し、保存された座標と jma の正確な座標が一致することを確かめる。locations 側だけに残る過去の地点は使わない。origin の Point が nil なら探索せず ErrInvalidArgument。標高だけ nil なら候補を返し、ElevationDifferenceMeters を nil とする。候補0件は空の配列で成功する。

並びは Inside が true を先、同じなら DistanceMeters の小さい順、同じなら5桁の StationID の文字列順。Inside は町と地点の AreaCode の一致で決める。距離の近い区域外を区域内より先にしない。標高差は地点の標高−町の平均標高の符号つき有理数。除外する地点は呼び出す側が候補結果から外す。ライブラリは上限で候補を削ったり、次の地点を採用したりしない。

`Distance` は地球を半径6,371,008.8mの球とした大円距離。緯度経度の有理数をここで初めて float64 の度、続いてラジアンへ変える。haversine の中間値を [0,1] に収め、`2R*atan2(sqrt(h),sqrt(1-h))` で求める。返り値は丸めない。NaN・Inf・負の距離を返さない。距離の同値に epsilon を使わず、同じ float64 を同値とする。標高差と代表点は有理数を保ち、書き出しの桁は呼び出す側が決める。

### 3.6 エラー

geo・climate の両パッケージがそれぞれ次の sentinel と Error/Unwrap を持つ。エラー文字列の接頭辞は各パッケージ名とする。

```go
var (
	ErrInvalidArgument = errors.New("geo: invalid argument")
	ErrInvalidFormat   = errors.New("geo: invalid format")
)

type ReadError struct {
	Source string
	File   string
	Line   int
	Key    string
	Field  string
	Err    error
}

func (e *ReadError) Error() string
func (e *ReadError) Unwrap() error
```

引数の形の誤りは ErrInvalidArgument。ファイルや配列の中の形式・重複・照合の誤りは ReadError に ErrInvalidFormat を包む。climate の Key は地点 ID、geo は地物のコードまたはメッシュコード。Source は ZIPSource.Name、File は ZIP 内の名前。Line は表題を含む物理行番号、XML は InputPos から得る。GeoJSON は地物番号を Field（`Features[0].Geometry` 等）に残し、Line が取れなければ0とする。まだ分からない場所は空文字列。メモリ上の入力の照合では Source・File は空にする。

I/O・ZIP・CRC・復号・Close の失敗は元のエラーを包む。形式の原因もあるときは errors.Join で残す。errors.Is と errors.As で判定でき、失敗時に部分結果を返さない。ポインターと配列は nil、Point・Location・距離などの値型はゼロ値にする。Point の緯度・経度の nil、範囲外の値、nil の Boundaries、空や不正な対象コードも ErrInvalidArgument にする。人口0、標高欠損、区域外、候補0件はエラーにせず、前節の状態を返す。

| 代表点 | 既知の中心2点と人口1:3から1:3の平均を正確に求める。標高100m・300mなら250m。入力順を変えても同じ有理数、境界セルは分割しない |
| 欠損 | 人口正の1セルの標高欠損で全体の標高が nil、人口0セルの欠損は影響なし、総人口0で代表点も nil。欠損人口は0へ置換せず失敗 |
| 探索 | 遠い区域内を近い区域外より先にする、同距離で地点 ID 順、年の RMK 0は除く・有効な積雪0は残す、6要素別に候補が異なること、入力配列を変更しないこと |
| 距離と標高差 | 同一点0m、赤道上の経度差1度は Rπ/180、対蹠点は Rπ、符号つき標高差と nil、地点の丸め前の座標を使うこと |
| 整数の判定 | 正負・0の外積、世界範囲の座標差、int64の積を超える場合を小さな big.Int の参照計算と照合する。15桁の境界の両側、1/(3×10^15)度の差、水平辺・頂点、600・480・320の分母の換算、対応外の分母を確認する |
| 失敗 | nil・空・不正な座標/rollup、ZIP 重複/CRC/I/O、UTF-8/Shift_JIS 不正、表題・列数・重複・座標系・XML 名前空間・軽い輪の検査の不正。errors.Is/As と位置、部分結果 nil。自己交差や穴の位相の全検査を読み取りの期待値にはしない |

任意の実物テストは `GEO_TEST_ZIP_DIR` がある場合だけ動かす。未設定は Skip、指定したファイルが無い場合は失敗。3.1の3 ZIP を照合してから読み、通常 CI では取得しない。ほかの地域を加えるときは出典とハッシュを追加する。中心による割り当てのずれは実装時に実物で調べ、数値と比較方法を残す。外接矩形ありの処理で正しさを確かめてから格子索引の前後のベンチマークを取り、ワーカーでの並列化は測って効果がある場合だけにする。小さな fixture では外接矩形による絞り込みの有無でも所属が同じことを確かめる。

実物で頂点数・輪数・最大桁数、入力ごとの読み込み、人口メッシュの所属、代表点の計算、地点の所属の所要時間を測る。推測: 4県ぶんの ZIP が手元にある再計算は5分以内を目標にする。ライブラリでは利用者の地域数や通信時間を上限にせず、呼び出すコマンド側で全体を測る。達成するかは未確認であり、群馬の点数だけから実測した速さとは扱わない。

## 4. jma パッケージ

### 4.2 返り値の形

ZIP は `io.ReaderAt` とバイト数で受け取る。`archive/zip.NewReader` にそのまま渡せ、メモリ上の ZIP と開いたファイルのどちらも扱えるため。

```go
type ZIPSource struct {
	Reader io.ReaderAt
	Size   int64
}

func Read(monthly ZIPSource, index ZIPSource, elements []Element) (*Dataset, error)

type Dataset struct {
	Edition  int
	Stations []StationNormals
}

type StationNormals struct {
	Station Station
	Normals []Normal
}
```

- `elements` は1〜6個。次の6要素だけを受け付ける。空・未対応の番号・重複はエラーにする。取り込む要素の組み合わせは呼び出す側が渡し、既定の一覧は持たない
- 全地点を読む。`Edition` は2020、`Stations` は観測所番号の昇順、各 `Normals` は求めた要素番号の昇順にする。観測していない要素も、行があれば得られない状態として返す
- `Reader` は nil を渡さず、`Size` は正の数を渡す。読み取り中は元のバイト列を書き換えない。ファイルを開く・閉じる責任は呼び出す側にあり、`Read` は受け取った Reader を閉じない
- 失敗したら `nil, error` を返し、途中までの `Dataset` は返さない。取得日と取得したファイルのハッシュは呼び出す側が保持する。`Read` は取得日を推測しない

```go
type Element string

const (
	ElementTemperature      Element = "0500"
	ElementDailyMaximum     Element = "0600"
	ElementDailyMinimum     Element = "0700"
	ElementSunshineDuration Element = "3500"
	ElementMaximumSnowDepth Element = "6200"
	ElementSnowfallTotal    Element = "6300"
)

type Unit string

const (
	UnitDeciCelsius Unit = "0.1℃"
	UnitDeciHour    Unit = "0.1時間"
	UnitCentimeter  Unit = "1cm"
)

type Status int

const (
	StatusUnset Status = iota
	StatusOK
	StatusUnavailable
)

type Value struct {
	Integer int64
	RMK     int
	Status  Status
}

type Normal struct {
	Element   Element
	Unit      Unit
	Years     int
	StartYear int
	EndYear   int
	Monthly   [12]Value
	Annual    Value
}
```

| 要素 | 内容 | 単位 |
| --- | --- | --- |
| `0500` | 気温の月・年平均 | `UnitDeciCelsius` |
| `0600` | 日最高気温の月・年平均 | `UnitDeciCelsius` |
| `0700` | 日最低気温の月・年平均 | `UnitDeciCelsius` |
| `3500` | 日照時間の月・年合計 | `UnitDeciHour` |
| `6200` | 積雪の深さの月・年最大 | `UnitCentimeter` |
| `6300` | 積雪差1時間差の月・年合計（降雪の深さの合計に当たる） | `UnitCentimeter` |

`Monthly[0]` は1月、`Monthly[11]` は12月。年の値は CSV の13組目を `Annual` に入れ、月から計算し直さない。整数は元の単位のまま持つ。たとえば `-34`・`UnitDeciCelsius` は -3.4℃で、表示の値への換算は呼び出す側か指標の計算でする。float は使わず、2章の倍率と同じく正確な数で換算する。

RMK `8` は `StatusOK`、`0` は `StatusUnavailable`。RMK `0` でも整数を読み、実物どおり0であることを確かめるが、その0には数としての意味を持たせない。積雪の `Integer: 0, RMK: 8, Status: StatusOK` は有効な0cmで、得られない状態と区別する。`StatusUnset` は未初期化を表し、成功した返り値には含めない。

資料年数と統計期間は行単位で `Normal` に持つ。RMK `8` でも30年とは限らず、たとえば `50477` の `0500` は12年・2009〜2020年である。30年未満をエラーにしたり、状態を変えたりしない。資料年数と統計期間の0は元の0のまま返す。日照の推計の印とあわせ、掲載・比較に使う条件は呼び出す側が決める。

```go
type Coordinate struct {
	DegreesRaw         string
	MinutesRaw         string
	TotalMinutesTenths int64
}

type ObservationMark int

const (
	ObservationNone      ObservationMark = 0
	ObservationMeasured  ObservationMark = 1
	ObservationEstimated ObservationMark = 2
)

type Station struct {
	ID                     string
	Name                   string
	NameKana               string
	NameRoman              string
	Latitude               Coordinate
	Longitude              Coordinate
	AltitudeMeters         int64
	AnemometerHeightTenths *int64
	Precipitation          ObservationMark
	Wind                   ObservationMark
	Temperature            ObservationMark
	Sunshine               ObservationMark
	SnowDepth              ObservationMark
}
```

緯度・経度は度と分の文字列を桁・先頭の0も含めてそのまま持ち、計算用には `TotalMinutesTenths = 度 × 600 + 分 × 10` を持つ。0.1分単位の整数なら元の精度を保って比較でき、度への換算も `TotalMinutesTenths / 600` の有理数で正確に行えるため。たとえば `35` 度 `28.0` 分は21,280である。緯度・経度に float のフィールドは作らない。

地点の名前は右端の埋め草だけを除く。漢字名は全角空白（U+3000）、カナ・ローマ字名は半角空白（U+0020）を除き、名前の途中の空白や半角カナは変えない。高度は1mの整数で、`0026` は26、`-003` は -3として読む。風速計の高さは0.1mの整数で、`010.1` は101、全桁が空白なら nil にする。値の0と空白を区別する。

地点情報の印はそのまま `ObservationMark` に写す。日照の `1` は観測、`2` は気象衛星のデータなどから作った推計、`0` は観測なし。地点の種類から推測しない。日照以外で `ObservationEstimated` は返さない。地点の印から平年値の状態を上書きせず、値の有無は期間ごとの RMK で決める。

### 4.3 読み方

ZIP の項目を読み、展開したファイルをディスクに書かずに処理する。内部の処理は、地点情報の読み取り、月・年別の読み取り、番号の集合の照合、並べ替えの順にする。

#### ZIP の中のファイルを見つける

- ディレクトリの項目は `FileInfo().IsDir()` で除く。ファイル名を basename だけで比べたり、先頭のパスを補正したりしない
- 月・年別の通常ファイルは `^monthly/area([0-9]{2})/nml_amd_m_([0-9]{5})\.csv$` に合うものだけを受け付け、area の2桁が観測所番号の先頭2桁と一致することを確かめる。それ以外の通常ファイルはエラーにする。CSV が0個、同じ観測所番号のファイルが2つでもエラーにする
- 地点情報の通常ファイルは、完全一致する `amedas_station_index.csv` が1つだけでなければエラーにする
- ZIP のファイルはパスの辞書順で処理する。地点情報と月・年別の観測所番号の集合が一致しなければエラーにする。片方だけの地点は返さない。件数を1,298には固定しない
- 各ファイルは最後まで読み、読み取りと Close のエラーを返す。ZIP の破損や CRC の不一致を読み落とさない

#### 行と文字コード

両 CSV は Shift_JIS。`golang.org/x/text/encoding/japanese` の `japanese.ShiftJIS` で UTF-8 に変える。標準ライブラリに Shift_JIS のデコーダーがないため、公開ライブラリの依存に `golang.org/x/text` を加える。

固定長の検査は UTF-8 に変える前のバイト列で行う。LF または CRLF を1つだけ除き、ほかの空白や CR を削らない。最後の改行は無くてもよい。空行は読み飛ばさずエラーにする。BOM も除かない。行を読むときの I/O エラーを確認し、不正な Shift_JIS を置換文字（U+FFFD）として通さない。対象として復号した行に U+FFFD があればエラーにする。対象外の月・年別の行は、次の2点の検査だけで読み飛ばす。

#### 月・年別

まず全行で、改行を除いて143バイトであることと、10〜13バイト目（1始まり）が ASCII の数字4桁の要素番号であることだけを確かめる。求めていない要素なら、そのあとを解釈せず読み飛ばす。平年値種別・観測所番号・重複・資料年数・統計期間・値・RMK の検査は、求めた要素の行だけに行う。

フォーマット表の RMK は `0` と `8` だけだが、実物の `50066`（富士山）の風の要素（2200〜2700のうち13要素、資料年数14）には `7` がある。対象外の RMK まで検査すると、求めた6要素を読めなくなる。未確認: RMK `7` の意味。この章では意味を割り当てない。

求めた要素の行は32列に分け、カンマの位置と各列のバイト数を確かめる。引用符やエスケープは受け付けない。

| 列（1始まり） | バイト数 | 読むもの |
| --- | --- | --- |
| 1 | 2 | 平年値種別。`21` 固定 |
| 2 | 5 | 観測所番号。ASCII の数字5桁で、ファイル名の番号と一致 |
| 3 | 4 | 要素番号。ASCII の数字4桁 |
| 4 | 2 | 資料年数 |
| 5〜6 | 各4 | 統計開始年・統計終了年 |
| 7 + 2k（k = 0〜12） | 6 | 1〜12月・年の整数値 |
| 8 + 2k（k = 0〜12） | 1 | 同じ期間の RMK。`0` または `8` |

資料年数・年・値は左端の半角空白だけを除いてから読む。資料年数と年は `[0-9]+`、値は `-?[0-9]+` だけを受け付け、`strconv.ParseInt` で10進の整数にする。全桁空白、末尾や途中の空白、`+`、小数点、指数、桁あふれはエラーにする。先頭の0は10進として読む。資料年数と年は読み取ったあと `int` にする。RMK は空白を除かず1文字を読む。

資料年数は0〜30。統計期間は開始・終了とも0、または `1991 <= StartYear <= EndYear <= 2020` とする。期間が0なら資料年数も0、期間があれば資料年数は1以上かつ `EndYear - StartYear + 1` 以下とする。途中の欠測年があるので、期間の長さと資料年数が同じであることは求めない。RMK `8` が1つでもあれば資料年数と統計期間は0にできない。全期間が RMK `0` でも、数として読めた資料年数・統計期間はこの条件で検査して保持する。

求めた同じ地点・要素の行が2つあればエラーにする。ファイルの終わりで、求めた各要素の行が1つずつあることを確かめる。RMK が全期間0の行は「行がある」と数える。対象外の要素の件数や順序、全122行がそろうことは読み取り条件にしない。

#### 地点情報

表題2行は、改行だけを除いた次のバイト列とそれぞれ完全一致することを確かめる。2行目は10列であり、15列に補わない。

```text
Station Number,Station Name,Station Name,Station Name,Latitude,Latitude,Longitude,Longitude,Altitude,Height of Anemometer,Precipitation,Wind Speed,Temperature,Sunshine Duration,Depth of Snow Cover
,(Kanji),(Kana),,(degree),(minutes),(degree),(minutes),(m),(m)
```

データ行は111バイト、カンマ区切りの15列とし、復号前の列幅を `5,20,15,30,2,4,3,4,4,5,1,1,1,1,1` と照らす。引用符やエスケープは受け付けない。データが0行ならエラーにする。

| 列 | 読むもの |
| --- | --- |
| 1 | 観測所番号。ASCII の数字5桁。重複不可 |
| 2〜4 | 漢字名・カナ名・ローマ字名。復号して4.2の埋め草を除き、空ならエラー |
| 5〜8 | 緯度の度・分、経度の度・分。度は数字2桁・3桁、分は `[0-9]{2}\.[0-9]`。原文も保持 |
| 9 | 高度。`[0-9]{4}` または `-[0-9]{3}` の10進整数 |
| 10 | 風速計の高さ。`[0-9]{3}\.[0-9]` を0.1mの整数にする。半角空白5個なら nil |
| 11〜15 | 降水量・風・気温・日照時間・積雪の深さの印。各1桁 |

分は小数点を除いて分の10倍の整数にし、0〜599に限る。緯度の度は0〜90、経度は0〜180で、90度・180度なら分は0に限る。印は `0`・`1`、日照時間だけ `2` も許す。どの数も float を経由しない。

### 4.4 エラー

```go
var (
	ErrInvalidArgument = errors.New("jma: invalid argument")
	ErrInvalidFormat   = errors.New("jma: invalid format")
)

type ReadError struct {
	Archive   string
	File      string
	Line      int
	StationID string
	Element   Element
	Field     string
	Err       error
}

func (e *ReadError) Error() string
func (e *ReadError) Unwrap() error
```

引数の誤りは `ErrInvalidArgument` を包んで返す。入力の処理中の失敗は `*ReadError` を返す。`Archive` は `monthly` または `index`、`File` は ZIP 内のパス、`Line` は表題も含む物理行番号（1始まり）。まだ特定できない項目は空文字列、行に結び付かない失敗は `Line: 0` とする。`Field` は型のフィールド名（`Years`、`Monthly[0].RMK` など）、表題は `Header`、ファイル構成は `File`、行の形は `Line` とする。`Error` の文には分かっている場所と原因を含める。

形式の誤りは `ErrInvalidFormat` を包み、数の読み取りなどの元のエラーもあれば `errors.Join` で両方を残す。I/O・ZIP の展開・CRC のエラーは元のエラーを包む。`ReadError.Unwrap` は `Err` を返し、呼び出す側が `errors.Is` と `errors.As` で調べられるようにする。エラー文全体の一致は契約にしない。

| エラーにする場合 | 対象 |
| --- | --- |
| Reader が nil、サイズが0以下、要素の指定が空・未対応・重複 | 引数 |
| ZIP が読めない、展開・CRC・読み取り・Close に失敗 | 両 ZIP |
| 想定外の通常ファイル、必要な CSV なし、同じ地点のファイルが2つ、area と番号が不一致 | ZIP 内の構成 |
| 地点情報と月・年別で観測所番号の集合が違う | 両 ZIP の照合 |
| 行が143バイトでない、要素番号が4桁の数字でない | 月・年別の全行 |
| 列数・列幅・カンマの位置が違う、平年値種別が21でない、行とファイル名の観測所番号が違う | 求めた要素の行 |
| 同じ地点・要素の行が2つ、求めた要素の行がない | 求めた要素 |
| 値・資料年数・年が整数として読めない、桁あふれ、資料年数・統計期間が4.3の範囲外 | 求めた要素の行 |
| RMK が0・8以外、RMK 0なのに値が数の0でない | 求めた要素の13期間 |
| 表題が欠ける・想定と違う、データ0行、データ行が111バイト・15列・指定の列幅でない | 地点情報 |
| 観測所番号が5桁の数字でない・重複する、名前が空、数の形・座標の範囲が違う | 地点情報 |
| 印が0・1・2以外、日照以外の印が2 | 地点情報 |
| 不正な Shift_JIS、復号結果に U+FFFD がある | 地点情報と求めた要素の行 |

RMK `0`、積雪0cm、資料年数30年未満、日照の推計はエラーにしない。対象外の要素の RMK `7` も読み飛ばす。

### 4.5 テスト

標準の `testing` を使い、表で並べるテストにする。通信しない。`jma/testdata/` に置く元データは数地点の CSV だけにし、ZIP はテスト内で `archive/zip.Writer` を使ってメモリ上に作る。`bytes.Reader` とサイズを `Read` に渡す。

月・年別は `49236`（負の気温）、`49251`（正常な積雪0cm）、`50066`（対象外の RMK 7）、`50477`（資料年数12年・RMK 0）を置く。122行を保ち、空白の埋め草・半角カナ・改行を変えない。地点情報は表題2行と対応する4地点を切り出す。高度の負数や印の異常などは、テスト内で行を変えて作る。

`testdata/README.md` に出典（気象庁）、平年値の版（2020年・基準の統計期間1991〜2020年）、取得日（2026-11-15）、4.1の取得元 URL・両 ZIP の SHA-256、切り出した観測所番号と加工した範囲を書く。壊れた行や ZIP 全体は置かない。

| テスト | 確かめること |
| --- | --- |
| `Read` の正常系 | ディレクトリの項目を除く、求めた要素だけを返す、地点と要素の並びを固定、1〜12月と年の対応、6要素の単位、Reader を閉じない |
| 固定長と数 | 143バイト・32列・各列幅、左の空白、負の `-34`、先頭の0、月と年の値を計算し直さないこと、空白・小数・指数・`+`・桁あふれを断ること |
| 値の状態 | RMK 0の行があることと行なしの違い、RMK 0の0を使わないこと、RMK 8の積雪0cm、ゼロ値が OK でないこと |
| 付属する情報 | `50477` の12年・2009〜2020年、期間と資料年数の差を許すこと、日照の0・観測1・推計2を値の状態と別に返すこと |
| 対象外の行 | `50066` の風の RMK 7を読み飛ばし6要素を返すこと。対象外の値や種別を壊しても読み飛ばし、長さ・要素番号を壊すとエラーになること |
| 地点情報 | 表題2行の完全一致、Shift_JIS の漢字・半角カナと埋め草、度・分の原文、分の10倍と合計の整数、負の高度、風速計の高さの数値・空白、印の許容範囲 |
| エラー | 4.4の全条件。求めた行の RMK を7に変える場合も含む。行番号・地点・要素・フィールドと `errors.Is`・`errors.As` を確かめ、失敗時の Dataset は nil |
| ZIP と行の境界 | 不正な ZIP、重複した項目、CRC 不一致、途中の I/O エラー、LF・CRLF・最終改行なし、途中の空行、不正な文字コード |
| `ExampleRead` | 数地点の CSV から作ったメモリ上の ZIP で動かし、使い方として pkg.go.dev に出す |

本物の ZIP 全体のテストは `TestReadFullZIP` とし、環境変数 `JMA_TEST_ZIP_DIR` に両 ZIP のあるディレクトリを渡したときだけ動かす。未設定なら `t.Skip`、設定されているのにファイルがない・読めないときは失敗にする。テストからダウンロードしない。

全体のテストは、まず4.1の SHA-256 と一致することを確かめ、6要素を指定して `Read` を呼ぶ。1,298地点・各6要素・13期間、RMK の件数、地点情報の印の件数を4.1と照合する。元の行の長さと122要素の件数も集計する。ZIP の版が変わったら、相違を確認して期待値と出典を更新する。通常の CI は環境変数を設定せず、小さな CSV だけで動く。
