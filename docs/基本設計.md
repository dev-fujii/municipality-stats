# municipality-stats 基本設計

状態: 確定（2026-11-15）。中の型と関数は [詳細設計](詳細設計.md) に書く。2026-11-16 に見直した（書き出しの持ち主、データファイルの扱い、対象の県の書き方）。

## 目的と範囲

e-Stat の統計と気象庁の平年値を取り込み、市区町村ごとの値を出典・年・状態つきの汎用の型にまとめ、指標を計算する Go のライブラリを作る。静的な HTML への書き出しは、動かせる見本のコマンドと `example/` で見せる。

満たすことは次のとおり。

- 取り込む項目は呼び出す側が引数で渡す。ライブラリは特定の項目の一覧を持たない
- 値の無い理由（調べていない・得られない・秘匿）と、取り込みの失敗を区別して返す。値が無いことを 0 にしない
- 同じ入力からは同じデータが出る。取り込みと、そのあとの計算・書き出しを分け、取り込みのほかは外部の API を呼ばない
- テストで本物の API を呼ばない
- e-Stat のアプリケーション ID は環境変数で渡し、コードやファイルに書かない

最初は複数の県の市区町村で試し、全国（1,741市区町村）でも動く作りにする。

## 使うデータ

| 出どころ | 使うもの | 取り方 |
| --- | --- | --- |
| e-Stat | 社会・人口統計体系の市区町村データ（基礎データと社会生活統計指標の、廃置分合処理済みの表） | API 3.0 の getStatsData（JSON） |
| 気象庁 | 2020年平年値（気温・日最高気温・日最低気温・日照時間・最深積雪・降雪の深さの合計）と観測地点 | 「平年値ダウンロード」のアメダスの月・年別平年値と地点情報の ZIP（固定長の CSV） |
| 国土数値情報 | 行政区域（N03）。観測地点が市区町村の中にあるかの判定に使う | GeoJSON |
| 国土数値情報 | 鉄道（N02）の新幹線の駅。市区町村の代表点から一番近い駅と直線の距離を求める | GeoJSON |
| 国土数値情報 | 都道府県地価調査（L02）の住宅地の基準地。市区町村ごとの価格の中央値と地点の数を求める | GeoJSON |
| e-Stat の統計GIS | 国勢調査（2020年）の 500m メッシュの人口。市区町村の代表点を求めるのに使う | 1次メッシュごとの ZIP（カンマ区切りのテキスト） |
| 国土数値情報 | 標高・傾斜度4次メッシュ（G04-c、500m）の平均標高。人が住むあたりの平均標高を求めるのに使う（[詳細設計](詳細設計.md) の3章） | 1次メッシュごとの ZIP |

廃置分合処理済みの表は、合併前の値も今の市区町村の境界で並ぶので、年をまたいで比べやすい。統計表 ID は基礎データが `0000020201`（A 人口・世帯）〜`0000020211`（K 安全）、社会生活統計指標が `0000020301`〜`0000020311`。

どれも商用で使える条件で配られている。国土数値情報の行政区域は CC BY 4.0、鉄道と地価調査は国土数値情報の利用規約で商用可（出典と加工の明記が要る）、e-Stat は利用規約で商用可（CC BY 4.0 と互換）。ライブラリが加工したもの（代表点など）を使う側は、出典とは別に加工したことを書く。

### 観測地点の結び付け

市区町村ごとの代表点は、区域に中心が入る 500m メッシュの人口（総数）で重み付けした平均にする。区域の重心だと広い市町村では山の中に落ちるため。人口（総数）は秘匿されない項目なので、秘匿されたメッシュの合算を戻す処理は要らない。

観測地点は要素ごとに選ぶ。日照や積雪を測らない地点があるため。その要素の平年値がある地点のうち、区域の中の地点を先にし、無ければ代表点に一番近い地点にする。距離と標高差の上限、地点の例外の指定は呼び出す側が渡す。ライブラリは「近い地点を探す」までを持ち、「その地点を市区町村の代表に採るか」は呼び出す側が決める。標高の補正はしない。補正すると公式の値でなくなり、根拠を示しにくいため。

日照の平年値は、地点ごとに観測か推計かを返す。気象庁は2021年3月に気象官署以外のアメダスの日照計をやめ、気象衛星のデータからの推計に替えた。2020年の平年値も、それらの地点では推計値相当に補正してある。地点情報の ZIP の日照の印（1 観測、2 推計）で見分ける（詳細設計の4章）。

区域の中の判定の決まりは [詳細設計](詳細設計.md) の3章に書く。政令市の区を市にまとめるときは、呼び出す側が区から市への対応を渡す。ライブラリは対応の表を持たない（2026-11-16 決定）。

### 駅と地価

新幹線の駅は、N02 の事業者種別（`N02_002`）が新幹線の駅に、呼び出す側が渡す追加の駅（路線名・事業者・駅名の組）を足して候補にする（2026-11-28 に直した）。在来線の線路を走る区間（秋田・山形）の駅は N02 では在来線に分類されるため、ライブラリは追加の駅の一覧を持たず、渡された組が N02 に無ければエラーを返す。同じ駅は駅のグループ（`N02_005g`）で1つにまとめ、属する路線名を全部持つ。駅は線のデータなので、レコードごとに線の中点を位置にし、距離はグループの中で一番近いレコードまでにする。距離は代表点からの大円距離で、所要時間には換算しない。N02 に時刻表は無いため。

地価は、L02 の基準地を呼び出す側が渡す用途（住宅地は `000`）で選び、区から市への対応を当てて市区町村に分け、地点の数・価格の中央値・最小・最大・調査の年を返す。地点の数が偶数のときの中央値は、真ん中の2つの平均を円の整数に丸める（0.5 は切り上げ）。地点が0の市区町村は「地点なし」の状態にし、0円にしない。呼び出す側が渡した市区町村の一覧に無いコードの地点があればエラーを返す（林地の `PP900` は林地の用途を選んだときだけ現れる）。1つの資料の中で調査の年が混ざればエラーを返す。地価公示（L01）とは時点が違う（L01 は1月1日、L02 は7月1日）ので混ぜない。何地点から使うかは呼び出す側が決める。

## 全体の構成

```
e-Stat API ──▶ estat ──┐
                       ├──▶ まとめ ──▶ 汎用の型 ──▶ 指標の計算 ──▶ 使う側（保存・書き出し）
気象庁 ──────▶ jma ────┤
行政区域・メッシュ人口・駅・地価 ─▶ 地理 ┘
```

| パッケージ | 役割 | 状態 |
| --- | --- | --- |
| `estat` | e-Stat API を呼び、値と状態の並びに変える | 詳細設計の1章 |
| `jma` | 気象庁の平年値の ZIP と地点情報を読む。値・単位・RMK（正常値か統計値なしか）・資料年数・統計期間と、日照が観測か推計かを返す | 詳細設計の4章 |
| `geo` | 行政区域の読み込みと所属の判定、メッシュ人口からの代表点、人口で重み付けした標高。隣の区域・鉄道・地価は後続 | 詳細設計の3章に設計案（2026-11-22）。未実装 |
| `climate`（まとめの気象部分） | `geo` と `jma` から、要素ごとの近い観測地点を区域内優先で並べる。採用・上限・例外は呼び出す側が判断する | 地点の所属、要素別の候補探索、大円距離と符号つき標高差を実装済み（詳細設計3.5〜3.7）。他のまとめはこれから |
| `landprice` | L02 の GeoJSON（zip の中のもの）を読み、用途で選んで市区町村ごとの数・中央値・最小・最大を返す | これから（2026-11-28） |
| `rail` | N02 の駅の GeoJSON を読み、新幹線と追加の駅を選んでグループでまとめ、代表点から一番近い駅と大円距離を返す | これから（2026-11-28） |
| 指標の計算 | 取り込んだ値から、呼び出す側が渡す定義に従って表示の値を計算する（詳細設計の2章） | 詳細設計の2章 |
| `example/` | 取り込みから HTML・JSON の書き出しまでを通す小さな見本。ライブラリが外に見せる型には入れない | これから |
| `cmd/` | 見本のコマンド | これから |

`estat`・`jma`・`geo` は互いを知らない。`climate` が `geo` と `jma` を使う。他のまとめのパッケージ名は、その段階で決める。

書き出しをライブラリのパッケージにしないのは、テンプレートを実行するだけの薄い層を、外に見せる型として保守する利益が小さいため（2026-11-16 決定）。

## 入力

- 取り込む項目の一覧（統計表 ID と項目コード）と、対象の市区町村コード。呼び出す側が渡す
- e-Stat のアプリケーション ID。呼び出す側が環境変数から読んで渡す。見本のコマンドは環境変数 `ESTAT_APP_ID` を読む

## 出力

- 取り込んだ値の並び。1つの値は、市区町村コード・項目・年・値・状態・単位を持つ
- まとめた結果の汎用の型（`estat.Record`・気象の値・座標・地点の探索と結び付けの結果）。保存するデータファイルの形は使う側が決める。出典と取得日は、使う側が持てるように返す
- 指標の計算の結果。HTML と JSON の書き出しは `example/` の見本でする

## エラーの扱い

- 値の文字列が記号（「***」「-」「X」）のときは、エラーではなく状態として返す
- API が誤りを返したとき、通信に失敗したとき、知らない形の JSON が返ったときはエラーを返す。途中まで取れた値で続けない
- 呼び出す側は、エラーなら前のデータファイルを残して止まれるようにする

## テスト

- 標準の `testing` を使い、表で並べるテスト（table-driven）にする
- API を呼ぶ部分は `httptest` で差し替え、`testdata/` に置いた実際の返り値の JSON を返す
- `go vet`・`golangci-lint`・`go test` を CI で動かす

## 版

Go のモジュールの決まりに従い、`v0.x.y` のタグで版を付ける。外に見せる型と関数がまだ固まらないので、v1 にするまでは 0 のままにする。

- 外に見せる型や関数を変えて、使う側が直す必要があるときは x を上げる
- 使う側が直さずに済む変更（バグの修正・関数の追加・内部の整理）は y を上げる
- タグは main で CI が通った commit に付け、push する。一度 push したタグは付け直さない。Go のプロキシに残り、同じ版で中身が変わってしまうため
- 何を変えたかは GitHub のリリースの説明に書く
- go.mod の `go` の行は、開発に使う版ではなく、使う側に求める最低の版にする（今は 1.26.0）。CI は 1.26 の系列と最新の安定版の両方で回す（2026-11-16 決定）

## 段階

| 段階 | 中身 |
| --- | --- |
| 1 | `estat`: 値の文字列の読み取り、getStatsData の JSON を読む型、Client と続きの取得 |
| 2 | 見本のコマンドで e-Stat から取り込む |
| 3 | `jma` と地理の部品で、観測地点を市区町村に結び付ける |
| 4 | まとめと指標の計算 |
| 5 | `example/`（取り込みから書き出しまでの見本） |

## 詳細設計で決めること

- 各パッケージの型と関数（段階ごとに [詳細設計](詳細設計.md) に章を足す）
- 観測地点の結び付けの型（地点の例外の渡し方、結び付けた結果の型）

保存するデータファイルの形は、使う側が決める。ライブラリは汎用の型（`estat.Record`・気象の値・座標・地点の探索と結び付けの結果）までを持つ。
