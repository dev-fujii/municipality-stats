# municipality-stats 詳細設計

状態: 確定（2026-11-15）。基本設計は [基本設計](基本設計.md)。段階が進むたびに章を足す。今あるのは段階1の `estat` パッケージと、その次に作る指標の計算の決まり。

## 1. estat パッケージ

e-Stat API 3.0 の getStatsData を呼び、値と状態の並び（`[]Record`）に変える。

### 1.1 使う API

```
GET https://api.e-stat.go.jp/rest/3.0/app/json/getStatsData
```

| パラメータ | 値 | 理由 |
| --- | --- | --- |
| `appId` | アプリケーション ID | 必須。呼び出す側が渡す |
| `statsDataId` | 統計表 ID（`0000020201` など） | 1回の呼び出しで1つの統計表 |
| `cdCat01` | 項目コードをカンマでつなぐ | 同じ統計表の項目をまとめて取る。列挙は100個まで |
| `startPosition` | 前の応答の `NEXT_KEY` | 続きを取る |
| `limit` | 100000（既定） | 1回の上限。テストでは小さくして続きの取得を試す |
| `metaGetFlg` | `N` | 項目名や地域名は使わないので、応答を小さくする |

`cdArea` は指定せず、全国の地域を取ってから呼び出す側の地域の一覧で絞る。`cdArea` の列挙は100個までなので、4県の172でも分けて呼ぶ必要があり、全国に広げると18回に分かれる。全国を取れば、4県でも全国でも同じ呼び方で済む。件数は、地域（約1,900。都道府県・政令市の区を含む）× 項目 × 年で、1つの統計表で10万件を超えるときは続きを取る。2026-11-15 に今の18項目で数えると、統計表ごとに約1.1万〜16.8万件、8つの表で計約52万件で、続きを含めて11回ほどの呼び出しで済む。`cdArea` と `cdCat01` に101個を渡すと、`STATUS` 105（「値が多すぎます。100個以内で指定して下さい」）が返ることも同じ日に確かめた。

`replaceSpChars`（記号を 0 や NULL に置き換える）は使わない。記号の違いが値の無い理由を表すので、そのまま受け取る。

### 1.2 返り値の形

2026-11-15 に統計表 `0000020208`（住宅）を呼んで確かめた形。

```json
{
  "GET_STATS_DATA": {
    "RESULT": { "STATUS": 0, "ERROR_MSG": "正常に終了しました。", "DATE": "2026-11-15T16:35:00.175+09:00" },
    "PARAMETER": { "STATS_DATA_ID": "0000020208", "START_POSITION": 1, "LIMIT": 4 },
    "STATISTICAL_DATA": {
      "RESULT_INF": { "TOTAL_NUMBER": 34, "FROM_NUMBER": 1, "TO_NUMBER": 4, "NEXT_KEY": 5 },
      "TABLE_INF": { },
      "DATA_INF": {
        "NOTE": [
          { "@char": "***", "$": "調査又は集計していないもの" },
          { "@char": "-", "$": "データが得られないもの" },
          { "@char": "X", "$": "数値が秘匿されているもの" }
        ],
        "VALUE": [
          { "@tab": "00001", "@cat01": "H2130", "@area": "10201", "@time": "2023100000", "@unit": "ｍ2", "$": "102.55" },
          { "@tab": "00001", "@cat01": "H2130", "@area": "10424", "@time": "2023100000", "@unit": "ｍ2", "$": "-" }
        ]
      }
    }
  }
}
```

確かめて分かったこと:

- `VALUE` は配列だが、1件だけのときは配列でなくオブジェクト1つになる
- 値は `$` に文字列で入る。数のほか、記号「***」「-」「X」が入る。人口の少ない町村の住宅の項目は「-」で返る
- `NEXT_KEY` は数で、続きがあるときだけある
- `@time` は `2023100000` の形で、先頭4桁が年
- `@unit` は全角の文字を含む（`ｍ2`）
- `RESULT.STATUS` は 0 が正常。1 は「正常に終了しましたが、該当データはありませんでした」で、このとき `DATA_INF` が無い。appId が違うと 100
- `PARAMETER` に appId は入らない。実際の応答を `testdata/` に置いても appId は漏れない

未確認: `NOTE` が1件だけのときもオブジェクト1つになるか。`VALUE` と同じく両方を読めるようにする。STATUS 2 以上で 100 未満の意味。

### 1.3 値の文字列の読み取り

値の文字列を、元の文字列と状態に変える。

```go
type Status int

const (
	StatusOK           Status = iota // 数が入っている
	StatusNotSurveyed                // 「***」調査又は集計していない
	StatusUnavailable                // 「-」データが得られない
	StatusConfidential               // 「X」秘匿されている
)

type Value struct {
	Raw    string // e-Stat の "$" そのまま（"102.55" の桁を保つ）
	Status Status
}

func parseValue(s string) (Value, error)
```

決まり:

- 記号は3つを別々の状態にする。「公表値なし」のようにページに出す言葉へまとめるのは呼び出す側でする。取り込みの段階でまとめると、あとから理由を区別できない
- 数は `-?[0-9]+(\.[0-9]+)?` の形だけを受け付ける。「-」だけなら記号、「-12.3」なら負の数（人口増減率は負になる）
- 知らない記号、空の文字列、カンマを含む数はエラーにする。「不明」の状態で通すと、API の変化や読み漏れに気づけない
- 値は float64 にせず、文字列のまま持つ。計算するときに `math/big.Rat` に変え、丸めは表示の直前に1回だけする。float64 だと 102.55 が 102.5499… になり、四捨五入で桁がずれる
- 取り込みの失敗はここでは扱わない。失敗は `Client` がエラーで返し、呼び出す側がデータファイルに残す

`NOTE` に知らない記号が載っていたら、`Client` がエラーにする。記号の意味が変わったことに気づくため。

テストの表:

| 入力 | 状態 | エラー |
| --- | --- | --- |
| `102.55` | OK | なし |
| `0` | OK | なし |
| `-12.3` | OK | なし |
| `***` | NotSurveyed | なし |
| `-` | Unavailable | なし |
| `X` | Confidential | なし |
| `x`（小文字） | | あり |
| 空 | | あり |
| `1,234` | | あり |
| `1e3` | | あり |

### 1.4 JSON を読む型

JSON の形をそのまま写す型はパッケージの外に出さず、外には `Record` だけを見せる。

```go
type Record struct {
	TableID string // 統計表 ID
	Code    string // 項目コード（@cat01）
	Area    string // 地域コード（@area。5桁）
	Year    int    // @time の先頭4桁
	Unit    string // @unit
	Value   Value
}
```

- `VALUE` と `NOTE` は、配列とオブジェクト1つのどちらでも読める型にする。`UnmarshalJSON` で先頭の文字が `[` か `{` かを見る
- `@time` は10桁の数字でなければエラーにする
- 同じ統計表・項目・地域・年の `Record` が2つあればエラーにする。社会・人口統計体系の表は分類が `@cat01` だけなので、ほかの分類（`@cat02` など）がある表を渡したときに気づける

### 1.5 Client

```go
type Client struct { /* baseURL・appID・httpClient・limit */ }

func NewClient(appID string, opts ...Option) (*Client, error)
func WithBaseURL(u string) Option        // テストで httptest のサーバーに向ける
func WithHTTPClient(h *http.Client) Option
func WithLimit(n int) Option             // 既定は 100000

type Query struct {
	TableID string
	Codes   []string // 1〜100個
}

func (c *Client) GetStatsData(ctx context.Context, q Query) ([]Record, error)
```

- `appID` が空なら `NewClient` がエラーを返す。appId を環境変数から読むのは呼び出す側（見本のコマンドは `ESTAT_APP_ID`）
- `NEXT_KEY` があれば、それを `startPosition` にして続きを取る。`NEXT_KEY` が前の `startPosition` 以下なら、終わらない繰り返しを防ぐためにエラーにする。最後に件数が `TOTAL_NUMBER` と合うか確かめる
- `STATUS` が 0 以外なら `*APIError{Status, Message}` を返す。1（該当データなし）は `ErrNoData` を包んで返し、呼び出す側が `errors.Is` で見分けられるようにする。項目コードの書き違いで起きるので、黙って空にしない
- HTTP の状態が 200 以外ならエラー
- エラーの文に appId を入れない。通信の失敗で返る `*url.Error` は URL を丸ごと含むので、URL から appId を消してから包む。ログと GitHub Actions の出力に appId が出るのを防ぐ
- `ctx` が取り消されたら止める。待ち時間は `http.Client` の `Timeout`（既定60秒）で決める
- 呼び出しは1つずつ順に行い、並べて呼ばない。再試行もまだしない（定期実行は手で動かし直せる）

### 1.6 テスト

本物の e-Stat は呼ばない。`testdata/` に実際の応答を小さく切った JSON を置く。

| テスト | 確かめること |
| --- | --- |
| `parseValue` | 1.3 の表 |
| JSON を読む | `VALUE` が配列のときとオブジェクト1つのとき、`NOTE` に知らない記号があるとき、`@time` の形が違うとき、同じ `Record` が2つあるとき |
| `Client`（`httptest.Server`） | 続きの取得（`WithLimit` で2ページに分ける）、`STATUS` 1 と 100、HTTP 500、`ctx` の取り消し、エラーの文に appId が入らないこと、送ったパラメータ（`cdArea` を送らない、`metaGetFlg=N`） |

## 2. 指標の計算（次の段階）

取り込んだ `Record` から、呼び出す側が渡す指標の定義に従って表示の値を計算する部品を公開側に置く。定義の中身（どの項目をどう組むか、何を比べるか、文章）は呼び出す側が持つ。型と関数は段階4の前に書き足す。今決めている決まりは次のとおり。

- 計算は3つ。Value は項目1つの値、Ratio は同じ年の a ÷ b、Diff は基準の年から続く N 年の Σ(a − b)
- 年の決め方は2つ。Fixed は決めた年、Latest は2つの項目がそろう最新の共通の年。年は地域ごとではなく、指標ごとに対象の全地域で1つに決める。町ごとに年がずれると比べられないため
- 換算の倍率（scale）は計算のあとに掛け、丸めは最後に1回だけ四捨五入する。負の数は絶対値で四捨五入する（-1.25 を小数1桁にすると -1.3）
- 倍率は `*big.Rat` で受け取る。float で受け取ると 0.1 が正確な 0.1 にならないため。文字列から `*big.Rat` を作るのは呼び出す側で、部品は受け取った `*big.Rat` を書き換えない
- 入力に OK でない値があれば、結果も OK にしない。分母が秘匿なら結果も秘匿にする。0 で割るときは「計算できない」の状態にする。N 年のうち1年でも欠ければ、途中までの合計を出さない
- 最新の共通の年の値が秘匿でも、黙って前の年に戻さない
